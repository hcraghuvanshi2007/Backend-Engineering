### What is package.json?
→ **_package.json_** is a JSON file in your project root that describes your project and lists all its dependencies. It's like a resume for your Node.js project.
#### Why Important:
1. Collaboration
2. Deployment
3. Version management
4. Automation

#### Creating & Using _package.json_:
##### **Easy Analogy:**

package.json = project blueprint.  
Lists all ingredients (packages) your app needs  

**How to use it:**
* npm init -y (create with defaults)  
* Edit manually or npm install <package> (adds to dependencies)  
* Each package gets entry: "express": "^4.18.2"  
* Share package.json, others run npm install to recreate setup  
* Never commit node_modules, only package.json + package-lock.json  

#### _package-lock.json_ — Why It Exists??
1. package-lock.json is automatically generated by npm install.
2. It records the EXACT version of every installed package and all its sub-dependencies.
3. Ensures every developer on the team installs identical versions.
4. Prevents 'works on my machine' problems caused by version drift.
5. Should ALWAYS be committed to Git — never add to .gitignore.
6. package.json = what you want (ranges).
7. package-lock.json = what you actually got (exact versions).

#### Local vs Global Packages

| Feature | Local Package | Global Package |
| :--- | :--- | :--- |
| **Installation Location** | Installed in `node_modules/` inside the project | Installed in system-wide npm directory |
| **Availability** | Only available in that project | Available as CLI commands anywhere |
| **package.json** | Listed in `package.json` dependencies | **NOT** listed in `package.json` |
| **Sharing** | Shared via `package.json` (not `node_modules`) | Must be installed separately on each machine |
| **Used for** | `express`, `mongoose`, `axios`, `dotenv` | `nodemon`, `create-react-app`, `pm2` |
| **Install Command** | `npm install <package>` | `npm install -g <package>` |

### Modules
→ Modules are self-contained units of code.  
* Each file in Node.js is a separate module with private scope.  
* Variables don't leak globally unless you export them.

##### Key Points:
* Encapsulation = hide implementation, expose API only
* Reusability = write once, use in many files
* Organization = code broken into logical units
* Scope isolation = avoid global namespace pollution
* Clear dependencies = see what each module needs

#### Why Modules Matter ??
**Use Case :**  
* Without modules, all code would be global.  
* Variables clash. Difficult to maintain.   
* Can't reuse code. Modules solve all these problems

**Why Important :**
* Scalability  
* Maintainability
* Reusability 
* Testability

  * **_Create once → Export → Reuse multiple times → Build bigger systems faster._**

### Types of Modules
| Type                    | Description                                            | How to Import           | Examples                                           |
|-------------------------|--------------------------------------------------------|-------------------------|----------------------------------------------------|
| **Core Modules**        | Built into **Node.js**. No installation needed.        | `require('module')`     | `fs`, `http`, `path`, `os`, `crypto`, `dns`, `url` |
| **Local Modules**       | Files that **you create** in your own project.         | `require('./myModule')` | `./math`, `./user`, `./database`                   |
| **Third-party Modules** | External packages installed from the **npm registry**. | `require('package')`    | `express`, `mongoose`, `axios`, `dotenv`           |

#### 1. _Core Modules_ — No Installation Needed
* Core modules are compiled into the Node.js binary — no npm install required.  
* Import with: const module = require('module-name');

| Module Name | Module Usage                             |
|-------------|------------------------------------------|
| **fs**      | File system read/write/delete operations |
| **http**    | Create HTTP servers and clients          |
| **path**    | File path manipulation utilities         |
| **os**      | Operating system information             |
| **dns**     | Domain name resolution                   |
